# FontRelay · Web 字体发布验收台

品牌官网从旧字体切换到新可变字体时，设计验收通常只看最终截图，看不到慢网、缓存命中、加载失败等条件下用户真正经历的过程。FontRelay 把字体加载到稳定的全过程做成可逐步回放的仿真：逐字符的**字体匹配、回退链、换行、尺寸与布局偏移（CLS）**都可见、可对比、可导出。

## 能看到什么

- **逐字符字体匹配**：每个字符实际由哪个 web 文件 / 系统回退字体绘制；缺失字形（.notdef）、合成字重（faux bold）单独标注。
- **真实换行与几何**：按字符前进宽度、字重轴、行高度量贪心排版，容器宽度可调——直接复现“德语按钮在字体加载后突然换行”。
- **逐步时间线**：`首屏 → 缓存命中 → 各文件到达 → 失败 → 重复注入提示 → 字体稳定`，单步 / 自动回放（快捷键 `←` `→` `空格`）。
- **故障注入**：慢网附加延迟、指定文件加载失败、强制缺失字形（越南语带调字符落系统字体）、缓存命中、同一 @font-face/link 重复注入。
- **A/B 发布版本对比**：双舞台同步步进，高亮字体发生变化的字符，自动定位**第一次视觉变化**时刻与稳定态 Δ高 / ΔCLS / Δ回退字符。
- **撤销 / 重做**（`⌘/Ctrl+Z`、`⇧⌘Z`）、**刷新恢复**（配置与持久缓存写入 localStorage）、**验收记录导出**（JSON / Markdown，含 CLS 门槛判定）。

## 快速开始

```bash
npm install
npm run dev       # 本地开发
npm test          # 运行全部测试（46 个）
npm run build      # 类型检查 + 生产构建
```

## 建议的验收路径（复现灰度问题）

1. 语言选「德语」，容器宽度拖到 240–320px，观察首屏按钮 1 行；逐步播放到 latin 文件到达，按钮变成 2 行、首屏整体位移——顶部 CLS 与「最大偏移」徽章给出量化值。
2. 语言切「越南语」，播放到 640ms：大部分字符已切换为新字体，而 `ả` `ệ` 等带调元音仍是系统 Tahoma（橙色虚线下划线），直到 1280ms vietnamese 子集到达。
3. 在「加载条件」里勾选 latin-ext/vietnamese 文件失败或输入强制缺字，确认相关字符最终留在回退字体、验收判定不通过。
4. 点击「缓存本次成功文件」后勾选「热缓存（刷新恢复）」，再看一次：首屏即新字体、CLS = 0，模拟刷新后二次访问。
5. 打开「对比 A/B 两个发布版本」，时间线自动定位两版本第一次几何差异；点「记录本次验收」并导出 Markdown 归档。

## 架构

纯逻辑核心（`src/core/`，不依赖 DOM、可单测）：

| 模块 | 职责 |
| --- | --- |
| `coverage.ts` | 字符集合 / 子集覆盖 / CJK 判定 |
| `matcher.ts` | 逐字符沿字体栈匹配 web 文件与系统回退、字重轴解析、字符宽度 |
| `layout.ts` | 贪心换行（词间 + CJK 任意断点）、行盒子与元素几何 |
| `loader.ts` | 加载事件规划：延迟、失败、缓存命中、重复注入去重 |
| `relay.ts` | 时间线引擎：逐步快照、布局偏移事件、CLS 汇总 |
| `compare.ts` | 两版本逐步对比与首次视觉变化定位 |
| `history.ts` | 通用撤销 / 重做栈 |
| `records.ts` | 验收门槛判定、记录、JSON/Markdown 导出 |

React 层（`src/components/`、`src/state/`）负责配置、舞台渲染、回放、持久化与记录。

## 说明

字体度量（字符前进宽度、行高系数）是为复现灰度现象而建立的**确定性仿真模型**，并非对某个真实字体文件的度量读取；接入真实 woff2 时，可把 `FontFile.metrics` 替换为字体度量工具（如 fontkit）的实测值，仿真管线其余部分无需改动。
